# Document & Annotation Quality Toolkit

Two runnable Python projects connecting AI data experience with backend engineering: an **invoice-text validation service** and a **YOLO detection-label auditor**.

**Python · FastAPI · Pydantic · Decimal arithmetic · Pytest · CLI**

[Portfolio](https://github.com/ajmal335) · [Walkthrough](docs/WALKTHROUGH.md) · [Example reports](examples/reports.json)

## Projects

| Project | Input | Output |
|---|---|---|
| Invoice Text Validator | Labeled text from an OCR/export pipeline | Extracted fields, line evidence, missing/duplicate fields, date and total checks |
| YOLO Annotation Auditor | YOLO detection label text and class count | Invalid classes, nonfinite coordinates, bad boxes, duplicates, and valid-box count |

The invoice service is a deterministic post-OCR baseline; it does not read images or call an LLM. The annotation auditor checks label geometry and syntax, not visual labeling accuracy. Both use synthetic examples and contain no employer or client datasets.

## Run locally

Python 3.11+ recommended.

```bash
git clone https://github.com/ajmal335/data-annotation-and-dataset-quality-work.git
cd data-annotation-and-dataset-quality-work
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m uvicorn quality_tools.api:app --host 127.0.0.1 --port 8000
```

On Windows, use `.venv\Scripts\activate`. API documentation: http://127.0.0.1:8000/docs.

### CLI (standard library only)

```bash
python -m quality_tools.cli invoice examples/invoice_valid.txt
python -m quality_tools.cli yolo examples/yolo_valid.txt --classes 2
```

Exit codes: **0** valid report; **1** validation issues; **2** invalid input/file/arguments. Validation failure is an expected outcome, not a tool crash.

## API examples

```bash
curl -X POST http://127.0.0.1:8000/invoices/validate \
  -H 'Content-Type: application/json' \
  -d '{"text":"Invoice Number: DEMO-001\nInvoice Date: 2026-10-19\nCurrency: PKR\nSubtotal: 1000.00\nTax: 160.00\nTotal: 1160.00"}'

curl -X POST http://127.0.0.1:8000/annotations/yolo/validate \
  -H 'Content-Type: application/json' \
  -d '{"text":"0 0.5 0.5 0.4 0.4","class_count":2}'
```

A valid API request returns HTTP 200 with `valid: true` or `valid: false`; malformed request fields return 422. `GET /health` reports liveness.

## Validation rules

**Invoices:** required invoice number, ISO date, currency, subtotal, tax, and total. Dates must be real calendar dates. Amounts must be nonnegative, at most two decimals, with optional correctly grouped thousands separators. Decimal arithmetic checks `subtotal + tax == total`. Duplicate fields are flagged rather than silently overwritten. Evidence includes original values and line numbers. Supported currencies: PKR, USD, AED, EUR, GBP.

**YOLO:** each nonblank row must contain `class_id x_center y_center width height`. Class IDs must be within the supplied range. Coordinates must be finite and normalized; width and height must be positive. Boxes must fit within the image, allowing a small floating-point tolerance. Exact duplicate boxes are flagged. Empty text is accepted as a background-image label; a missing label file is not automatically classified as background.

## Verification

**31 automated tests passed** during the October 2026 implementation, covering malformed fields, decimal arithmetic, duplicate evidence, out-of-bounds boxes, NaN/infinity, background labels, and API request validation. [Example reports](examples/reports.json) were generated by running the code on the bundled fixtures. These are engineering checks, not a benchmark on real invoices or images.

## Docker

```bash
docker build -t dataset-quality .
docker run --rm -p 127.0.0.1:8000:8000 dataset-quality
```

Docker configuration is included but was not built during implementation. The API stores no submitted records. Invoice reports contain the input's extracted values; treat them as sensitive if using real documents. Authentication and production request limits are not included, so keep this demonstration bound locally.

## Limits and next steps

- No OCR, arbitrary-layout understanding, discount/shipping handling, credit notes, or document authenticity checks.
- No image/label pairing, dataset-wide class balance, or assessment of whether a box covers the correct object.
- No trained model or claimed AI accuracy in these validators.
- Next steps: add a replaceable OCR adapter, labeled extraction evaluation, and a dataset-directory audit command.
